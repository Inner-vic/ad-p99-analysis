# 运维与失败恢复

授权状态以固定 profile/App/User 为准；`auth status` 的本地 fresh 状态与真实 scope/资源可用性分开判断。只有首次发送尚无任何上游消息时才允许同一幂等键刷新后重试一次；已有派发证据不重发整单。新环境安装、预检、旧失败解释和状态查询均不授权新的车辆任务。

| 精确记录状态 | 处理 |
| --- | --- |
| 无 comparison_key 且确认无任何上游消息 | 检查前次失败与原始请求，获准后在原记录执行 worker；不新建来源记录 |
| 已有 comparison_key | resume 只收已有卡片并继续处理，不重发 fsdlog |
| 已有 report_url | 复用原文档，补持久化的权限/所有权/L3/撤销和回传步骤 |
| 发送意图存在但回执未知 | 人工核对真实消息，不盲目补发 |
| completed 且有真实来源绑定回执 | 复用结果，不重复外部写入 |

下载的瞬时网络错误最多三次整文件尝试，长度校验后原子替换；4xx、认证、重定向和白名单错误不重试。卡片分页截断、阿斯加德身份不符、VIN/时间冲突、多 URL 或不完整结果一律不认领。旧单任务兼容逻辑不能证明其他人工或服务派发的同窗卡片归属，上游明确 reply 关联优先。

维护健康文件只写允许的脱敏元数据；不要提交 CLI stdout、token、原始表格或签名下载 URL。`20140` 是管理员配置问题；明确 refresh 撤销用受控 split-flow，普通网络失败不重置身份。详见飞书接入与 Skill 上游恢复契约。
